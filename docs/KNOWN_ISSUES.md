# KNOWN ISSUES — Invoice Processing System Enhancement

Only genuine, currently-true issues. Nothing speculative and nothing
resolved is listed as open.

| # | Issue | Impact | Status / mitigation |
|---|---|---|---|
| K-1 | The project folder is OneDrive-synced; SQLite files can corrupt under concurrent access (baseline risk T-3). A background writer exists since Sprint E1. | Low (single user) | Serial worker + short transactions implemented; unreadable-file errors are classified retryable (TC-PIPE-FAIL-02); transient SQLite lock/busy errors during claiming or persistence are retried with backoff, bounded by `WORKER_DB_MAX_ATTEMPTS` (Sprint E1 review M2, TC-DBLOCK-01..04) — on exhaustion the row keeps its eligible status and boot-time recovery picks it up; advise pausing OneDrive sync while the app or tests run |
| K-2 | The role mechanism (Sprint E4) is session-based and provides **no authentication** — any browser user can switch roles. | None for the single-user localhost app; blocks any multi-user use | Documented as a workflow demonstration, not a security boundary (ARCHITECTURE.md §6) |
